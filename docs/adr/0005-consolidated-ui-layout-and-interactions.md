# Consolidated Search Workbench, Saved Search Controls, Status Tooltips, and Watchlist UI

Status: accepted

Unified Marketplace Search v1 will use a persistent **Workbench Sidebar** layout (Variant A from the issue #11 UI prototype) pairing a left sidebar—containing primary navigation (**Search**, **Watchlist**, **Settings**), a bounded scrollable **Saved Searches** panel (overflowing smoothly after ~6 entries with stable insertion order on selection, an inline compose/edit rename icon immediately to the right of the **Saved Search** name, a top-right `×` delete icon with `<dialog>` confirmation, a bottom-right relative `lastRunAt` timestamp, and explicit dirty-state **Update Saved Search** / **Save as New** actions), and stacked **Unified Filter** controls (`priceMin`/`priceMax`, 5-tier multi-select `Condition`, `Fulfillment` with ZIP/radius, and **Facebook City Hubs**)—with a main workspace holding the required `keywords` bar, pre-run **Marketplace** arming toggles, a 4-card per-**Marketplace** status strip, a post-run visibility filter & sort toolbar (with **"Include known shipping in price sort"**), a multi-column **Listing** card grid, and a stateful **"Load more Listings"** footer. Each **Marketplace** status card displays its **Marketplace** badge, loaded **Listing** count, translation/execution badge (`Exact`, `Broadened`, `Skipped (unsupported)`, `City X of Y`, `Challenge`, `Circuit breaker`), an `i` info trigger revealing diagnostic prose inside a card-width `popover="hint"` tooltip on hover/focus/click, inline fail-soft recovery actions (`Open on <Marketplace> ↗`, `"Open browser session"`, `"Retry <Marketplace>"`), and—when Facebook Marketplace is actively sweeping—an inline animated loading spinner next to its **Marketplace** badge that turns into a red `×` stop icon on hover/focus. Streaming **Listings** follow the latched scroll-safe buffer pill (`"+N new Listings — Click to merge"`) and persistent gold `"New"` badge semantics in ADR-0004, while **Watchlist** (flat PII-free **Watchlist Entries**, base-price sort with `null` at bottom, **Marketplace** filter, cached-thumbnail/expired-placeholder display, and instant removal + `Undo` `popover="manual"` toast) and **Settings** (eBay `client_id` + masked `client_secret` replace/verify, Chrome/Edge channel, `%LOCALAPPDATA%\unified-marketplace-search\` path, Home ZIP/radius and optional Home Facebook City Slug, customizable 500-mile **Facebook City Hubs**, per-**Marketplace** `"Open browser session"` / profile reset, and `"Stop server"`) render in the main pane.

## Considered Options

- **Full-Width Command Bar (Variant B) and Split Triage + Watchlist Dock (Variant C):** Variant B hid **Unified Filters** and **Saved Searches** behind header popovers, making active filter state less scannable; Variant C's horizontal triage rows and sticky right dock sacrificed card density and visual thumbnail scanning compared to Variant A's multi-column **Listing** grid and persistent sidebar.
- **Re-ordering the Saved Search list by `lastRunAt` descending on selection (Issue #6 rule):** Rejected after prototype review because clicking a **Saved Search** and seeing it jump to the top of the list disorients muscle memory; list order now stays fixed on selection while `lastRunAt` updates in place.
- **Inline status diagnostic prose, card-wide tooltip hover, and standalone `"Stop Facebook sweep"` button:** Inline prose bloated healthy status cards vertically, card-wide hover triggered distracting popovers while moving toward action buttons, and a standalone stop button added noise when an inline spinner-to-`×` toggle next to the **Facebook Marketplace** badge conveys both progress and cancellation in one spot.
- **Unlatching the merge pill automatically when scrolling back to the top and fading `"New"` badges after 10 seconds:** Replaced in alignment with ADR-0004 because auto-merging on scroll-up risks unexpected grid shifts before the user is ready, and a persistent gold `"New"` badge makes newly merged **Listings** easy to distinguish throughout a search run.

## Consequences

- **Issue #6 ordering override:** **Saved Searches** still record `lastRunAt` (displayed at the bottom right of each panel), and newly created **Saved Searches** prepend/insert cleanly, but clicking an existing **Saved Search** to run it does **not** re-order the sidebar list—explicitly superseding the `lastRunAt`-descending re-order rule from issue #6.
- **Native top-layer UI primitives:** Confirmation dialogs (delete **Saved Search**, reset browser profile) use native modal `<dialog>`, status diagnostics use card-width `popover="hint"` tooltips (`interestfor` + `popovertargetaction="show"` with CSS Anchor Positioning and `getBoundingClientRect()` fallback), and **Watchlist** Undo notifications use `popover="manual"` toasts inside an ARIA region.
- **Prototype archive:** The full interactive three-variant throwaway prototype (`prototype/consolidated-ui.html`) is preserved as a primary source on branch `prototype/consolidated-ui` and excluded from `main`.
