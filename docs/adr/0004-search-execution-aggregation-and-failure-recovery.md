# Progressive Search Streaming, Listing Normalization, Cross-Marketplace Aggregation, and Partial-Failure Recovery

Status: accepted

Unified Marketplace Search v1 will execute on-demand searches via a server-orchestrated streaming run (SSE / NDJSON on `/api/searches/stream`) that fans out eBay (`fetch`), Poshmark (`patchright` warm page executing same-origin `fetch('/vm-rest/posts?...')` for page 1 and `more.next_max_id` pagination), and Mercari US (`patchright` intercepting `searchFacetQuery`) in parallel alongside a single-tab sequential sweep across enabled **Facebook City Hubs** (parsing initial SSR `<script type="application/json">` Relay JSON followed by `CometMarketplaceSearchContentPaginationQuery` scroll pagination) with a 3–5s jittered cooldown and `(marketplace: 'facebook', marketplaceListingId)` deduplication. Every adapter validates top-level response envelopes before performing resilient per-node normalization into a canonical **Listing** schema (on eBay: setting auction `price` to `currentBidPrice` with `listingFormat`/`bidCount`/`buyNowPrice` metadata, reading `additionalImages[]`, and stripping raw `seller` objects for exemption compliance; on Poshmark: filtering `inventory.status === 'available'`, normalizing `shipping_discount_type` `'free'` → `0` / `'free'`, `null` → `6.49` / `'known'`, `'discounted'` → `null` / `'buyer_paid_unknown'`, and deriving `listedAt` from `first_published_at ?? created_at`; on Mercari US: dividing integer-cent `price` by `100`, reading `photos[0].thumbnail`, converting `created` Unix epoch to `listedAt`, and normalizing grid shipping to `shippingPrice: null` / `shippingType: 'unknown'` since grid `shippingPayer`/`shippingClass` are `null`; on Facebook: setting `shippingType` to `'buyer_paid_unknown'` when `delivery_types.includes('SHIPPING_ONSITE')` else `'local_pickup_only'`, and converting `creation_time` Unix epoch to `listedAt`; plus enforcing local active-only and `priceMin`/`priceMax` post-filters). The consolidated view merges **Listings** via deterministic round-robin native-rank interleaving (including across **Facebook City Hubs**) for `relevance`, sorts `newest` globally by `listedAt` descending across all four **Marketplaces** (placing any `listedAt === null` **Listings** after timestamped **Listings** ordered by `adapterRank`), sorts `price_asc`/`price_desc` by base `price` with known shipping as tie-breaker (plus an instant client-side **"Include known shipping in price sort"** toggle), buffers mid-stream batches behind a `"+N new Listings — Click to merge"` pill once the user scrolls past the top ~2–3 grid rows (highlighting newly merged cards with a persistent gold `"New"` badge), supports stateful `"Load more"` pagination, caches identical adapter batches in memory for 60 seconds, and isolates per-**Marketplace** failures with zero automatic browser retries, a Facebook mid-sweep circuit breaker, and targeted single-**Marketplace** retry after `"Open browser session"`.

## Considered Options

- **Single blocking HTTP response or client-orchestrated per-Marketplace / per-city HTTP calls:** A blocking response stalls the UI for 25–40+ seconds during an 8-city Facebook sweep, while client-orchestrated calls leak single-tab profile locking and cooldown enforcement into browser JavaScript.
- **Sorting `price_asc` / `price_desc` unconditionally by `price + (shippingPrice ?? 0)`:** Penalizes **Marketplaces** that report known shipping fees (such as Poshmark's $6.49 flat rate or eBay's explicit shipping) by treating Mercari US (`unknown`) and Facebook `buyer_paid_unknown` (`shippingPrice: null`) **Listings** as `$0` shipping.
- **Round-robin `adapterRank` interleaving for `newest`:** Rejected after live 2026 verification confirmed all four **Marketplaces** return creation timestamps on grid payloads (`itemCreationDate`, `first_published_at`/`created_at`, `created`, `creation_time`), because round-robin interleaving could surface stale **Listings** above freshly posted deals; users can already isolate any **Marketplace** with the post-run filter strip.
- **Running a second parallel `shippingPayerIds=2` Mercari US query to detect free shipping:** Rejected because Mercari grid `itemsList` nodes return `shippingPayer`/`shippingClass` as `null` even when filtered; normalizing Mercari grid shipping to `shippingPrice: null`, `shippingType: 'unknown'` avoids doubling browser requests and pagination state while base-`price` sort remains unaffected.
- **Immediate in-place grid splicing while scrolled down:** Causes cards under the user's cursor to jump mid-read as slower **Marketplaces** and Facebook City Hubs stream in over 25–40 seconds.
- **Batch-failing an adapter on single-node JSON parse errors or auto-retrying failed browser navigations:** Feed responses frequently interleave non-**Listing** modules (carousels, ads) that should be skipped rather than triggering `parse_error`, and automatically retrying challenged `patchright` tabs risks worsening anti-bot lockouts.

## Consequences

- **Scroll-safe progressive UI & persistent gold `"New"` badges:** The frontend tracks when the user scrolls past the forgiving top scroll zone (~2–3 rows / ~400–600px) and latches pending-buffer accumulation behind the `"+N new Listings — Click to merge"` pill until the pill is explicitly clicked (even if the user scrolls back to the top), highlighting newly merged **Listing** cards with a persistent gold `"New"` badge for the duration of the search run.
- **Stateful search run cursors & 60-second adapter cache:** The Hono server maintains short-lived in-memory run state (`searchRunId`) pairing eBay `offset` increments with same-origin `/vm-rest/posts` `more.next_max_id` (`ENC_...`) pagination on Poshmark (sharing one unified normalizer with page 1) and controlled single-scroll pagination on warm Mercari and Facebook `patchright` pages, backed by a 60-second query cache (`(marketplace, keywords, unifiedFilters, sortOrder, page)`) bypassed on explicit `"Refresh"` or `"Retry <Marketplace>"`.
- **Clear client vs. server action boundary:** Toggling **"Include known shipping in price sort"** or hiding/showing an already-queried **Marketplace** runs instantly in client memory; enabling a previously unqueried **Marketplace** or clicking `"Retry <Marketplace>"` runs a targeted single-**Marketplace** query; changing `keywords`, **Unified Filters**, or primary `SortOrder` initiates a new search run.
