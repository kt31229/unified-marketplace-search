# Per-Marketplace Access Strategies and Local Browser Posture

Status: accepted

To keep Unified Marketplace Search at $0/month on Windows while covering all four **Marketplaces** (eBay, Poshmark, Mercari US, and Facebook Marketplace), eBay will use the official Buy Browse API (`GET /buy/browse/v1/item_summary/search` via OAuth 2.0 `client_credentials` under the "Not persisting eBay data" Marketplace Account Deletion Exemption, live-verified at `5,000` calls/day with no Application Growth Check gate) as the sole v1 eBay adapter, while Poshmark, Mercari US, and Facebook Marketplace will use local installed Google Chrome automation (Edge configurable) with isolated dedicated `--user-data-dir` profiles (`poshmark`, `mercari`, `facebook`) and strictly JSON-only ingestion without DOM/CSS scraping: network JSON interception on Mercari US (`GET /v1/api?operationName=searchFacetQuery`) and Facebook Marketplace (`POST /api/graphql/` `CometMarketplaceSearchContentPaginationQuery`), same-origin `fetch('/vm-rest/posts?...')` inside the live `patchright` browser context on Poshmark (since initial `/search` SSR omits `window.__INITIAL_STATE__` and page-1 XHR), and embedded SSR `<script type="application/json">` Relay JSON on Facebook Marketplace. Poshmark and Mercari US run strictly unauthenticated (guest) to protect personal accounts, while Facebook Marketplace runs in a dedicated profile manually signed into a secondary Facebook account treated with full personal-account-grade safety guardrails. All browser-backed adapters fail soft on CAPTCHAs or login checkpoints (direct link-out plus an explicit `"Open browser session"` recovery action).

## Considered Options

- **Direct HTTP to Poshmark `/vm-rest/posts` (TLS spoofing):** Faster per query, but silently drops deep **Marketplace Filters** (`brand[]`, `size[]`, `color[]`, `availability`) and breaks against Cequence Security and `pm_version` churn.
- **Direct HTTP to Mercari `/v1/api` or Facebook `/api/graphql/`:** Non-viable at $0/month due to Cloudflare Managed Challenges / `401 Unauthorized`, rotating persisted-query hashes/`doc_id`s, and TLS fingerprinting.
- **Reusing the default Windows Chrome/Edge `User Data` profile or copying cookies:** Blocked by Chrome/Edge 136+ remote-debugging restrictions on default `User Data`, Windows `SingletonLock` collisions, and Chrome 127+ App-Bound Encryption.
- **Link-out only for Facebook Marketplace:** Eliminates Meta ToS/account risk, but drops consolidated Facebook **Listing** cards from v1.
- **Auto-popping browser windows mid-search and DOM-scraping fallbacks:** Steals Windows focus, increases Facebook checkpoint-flagging risk, and adds brittle selector maintenance against obfuscated CSS.

## Consequences

- **Local browser runtime requirement:** App architecture and tech stack selection must support driving installed Windows Chrome (`channel: 'chrome'`, Edge configurable) against three isolated dedicated profile directories (`facebook`, `poshmark`, `mercari`) in headless background contexts (`headless: true`, `--window-size=1280,900`, with non-`HeadlessChrome` User-Agent, live-verified to render `document.visibilityState === "visible"` without Windows taskbar flashing) for searches and explicit on-screen foreground windows (`headless: false`, `--window-position=80,80 --window-size=1280,900`) only on `"Open browser session"`.
- **Strict Facebook Marketplace guardrails:** Search execution must enforce user-initiated on-demand runs only (never on startup), max 1 active Facebook search run at a time using one dedicated tab per designated City Hub (driven sequentially one hub at a time so each hub retains its live pagination state across `"Load more"` clicks without losing track of pages), initial batch only by default (explicit `"Load more"`), mandatory cooldown between consecutive Facebook queries, manual one-time sign-in and `500 miles` (`805 km`) browse radius setup during `"Open browser session"` (which persists across city-slug navigations without per-search UI radius automation; never automating credentials/2FA), and immediate circuit-breaker abort on any login prompt or checkpoint.
- **eBay policy boundary:** **Watchlist Entries** must strip raw `seller` objects and remain strictly free of seller PII to stay aligned with the Account Deletion Exemption; the speculative local-Chrome eBay fallback is retired from v1 scope now that Production Browse API access is confirmed live at `5,000` calls/day with no Application Growth Check gate.
- **Pre-spec live verification:** All pre-spec live verification checks (issues #12, #13, and #14 spot-checks across eBay Production Browse API and Windows Chrome for Facebook Marketplace, Mercari US, and Poshmark) **passed**, confirming the v1 access posture for `/to-spec`.
